# Planning

Every line of the plan is context the implementer pays for.

- List the chosen work as steps in sequence, each bounded by a checkable completion criterion. Attach to a step a constraint the implementer must respect and cannot derive from the step or the rules already in force, such as the trade-off a choice accepts.
- Leave rejected options out of the plan. Keep one only when the user asks for a record of what was ruled out.
- Escalate a choice that outgrows the plan: ask the user when it is unclear or has surprising consequences. Flag it for an ADR when it is hard to reverse and will surprise future readers.

Done when the plan lists the chosen work in sequence with a checkable completion criterion on every step and contains no rejected options the user did not ask to keep.
